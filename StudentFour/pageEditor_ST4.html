User Profile

Technical Description

The User Profile page is divided into 2 sections besides the <header> and <footer>. One of the sections being for the profile completion bar and the other for the actual profile display.
Starting with the progress bar, I have used the .container class from the global template. Within this container is one progress bar that starts from zero, using JavaScript. The script for functionality of everything in this page is linked to profile.js. All of the style changes happens with JavaScript in this section, following as per the coursework description. The progress bar colour changes from red to green, showing progress from when its red for incomplete, and green for fully complete. Also depending on how many parts of the profile is complete, the width of the #progress-bar (which is the progress bar container) expands with JavaScript DOM. Right below the progress bar there is a .progress-message container which includes 2 of .left and .right. They include styling for sticking the #progress-message to the left and #profile-status to the right side of the screen. #progress-message contains how many fields in the profile has been completed. This starts with 0. #profile-status shows the condition of the user's profile. Depending on how many fields have been filled in, the profile status will dynamically update to show between Poor (0 - 3), Decent (4 - 7), Good (7 - 9), and Excellent (10).
Then we move to the second section (<div> without any attributes) which contains 3 sub sections; .prompt-input-pd, prompt-input-pref, prompt-input-other. These sub sections are encapsulated within a <fieldset> with border: 2px solid var(--bd-colour) to clearly differentiate the sub sections. Each of those classes have two classes; .left-field and .right-value. Just like with the classes .left and .right mentioned before, the left sticks to the left and the right sticks to the right. The left side has the field; user reads this and finds out what this line is about. The right side has the value; this acts as the display for the field, also as a button to update/change the value. Each value has its own button tag with unique IDs because they will update/change with JavaScript. Rather than using the normal <input> method that HTML has to take in user input, I used the JavaScript prompt() to take it user inputs just like how it has asked in the coursework description.

Accessibility

The prgoress bar is a very friendly user-friendly system to show user what their progress is without reading the numbers, because the colour changes with each field value completion. The use of fieldset and legend creates logical groupings that screen readers can announce, helping users understand the structure of the profile form. The first edition of the prompt system used to look very different and had a very non-user-friendly system of working. The current one I have impletement was inspired by the one we have in our VLE Blackboard. As you click on the button that says Enter Here, it prompts user what they want to enter there. If it already has a value, clicking on it again asks the user to change it. If the user inputs anything invalid or empty value, it skips it while also not updating the progress. Users will also be able to see if they are on the buttons with the :hover pseudoclass with a colour change and a little scaling effect. Each prompts for getting value are also clearly displayed.

Sitemap

Technical Description

The Sitemap page is very simple, showing how and where each of the pages in html pages are linked together as a website. Using the global template's .container, I laid out the premises of the SVG drawing. On it I have laid another div with class svg-wrapper, which makes it so that if the website is resized, the whole svg that is within this container resizer equally and not deform. The SVG is then declared with the viewBox attribute starting a rectangle with one point at (0 | 0) and the other end point at (1200 | 950). I chose these coordinates because it seems to work beautiful mathematically and symmertrically with the design I had in mind. The first thing is the SVG's <defs>, which is where I have kept some reusable drawable codes, one for the arrow head using <marker> and <polygon> which is seen pointing, and the other sections have the declaration for some gradient colours using <linearGradient> and <stop> which I have used for backgrounds of main connection nodes later. Drew a rectangle for the base using $lt;rect> and with the fill attribute, used hsl(40, 20%, 95%) which is this grey-ish colour that looks like roughly used paper. I also used this same colour for the .svg-wrapper to blend smoothly.
The splash screen has 3 main features. Main Node (generally main pages), Nodes (anything that connects) and Lines (node connectors). All of these have been grouped in a relavant way using svg's g tag. All the position coordinates for nodes and lines are hard coded after doing maths. I have also given each groups appropriate class names for working with CSS. The Main Nodes (.splash-node and .home-node) uses a bigger font and more bolder colour gradient. The other connected page nodes uses a little smaller font but the same size boxes. Then the content pages are all leading out from home-node. And from here on is where I have used dotted lines using the stroke-dasharray attribute for the line tag only because these I felt are a bit less relavant compared to the other pages. Then the supporting pages come out from the content pages which includes the page editor and the validation.

Accessibility

In the nodes, added the tabindex="0" attribute to make everything keyboard-focusable. I also have added the :hover and :focus pseudoclass on some classes so that it changes to show user they have a cursor on it or have selected something. Everything is responsive in the Sitemap. I have also added a legend below the SVG which shows what colour nodes lead to what kind of pages. Each <a> tag also contains descriptive text content, ensuring screen readers can announce the destination of each link. There also is another :focus pseudoclass on the .node-rect so the user knows which one they selected. Since the sitemap is active in the sitemap itself, the colour for the #sitemap-node is different compared to others.
