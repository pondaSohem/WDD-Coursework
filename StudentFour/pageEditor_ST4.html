User Profile

Technical Description

The User Profile page is divided into 2 sections besides the <header> and <footer>. One of the sections being for the profile completion bar and the other for the actual profile display. Starting with the progress bar, I have used the .container class from the global template. Within this container is one progress bar that starts from zero, using JavaScript. The script for functionality of everything in this page is linked to profile.js. All of the style changes happens with JavaScript in this section, following as per the coursework description. The progress bar colour changes from red to green, showing progress from when its red for incomplete, and green for fully complete. Also depending on how many parts of the profile is complete, the width of the #progress-bar (which is the progress bar container) expands with JavaScript DOM. Right below the progress bar there is a .progress-message container which includes 2 of .left and .right. They include styling for sticking the #progress-message to the left and #profile-status to the right side of the screen. #progress-message contains how many fields in the profile has been completed. This starts with 0. #profile-status shows the condition of the user's profile. Depending on how many fields have been filled in, the profile status will dynamically update to show between Poor (0 - 3), Decent (4 - 7), Good (7 - 9), and Excellent (10). Then we move to the second section (<div> without any attributes) which contains 3 sub sections; .prompt-input-pd, prompt-input-pref, prompt-input-other. Each of those classes have two classes; .left-field and .right-value. Just like with the classes .left and .right mentioned before, the left sticks to the left and the right sticks to the right. The left side has the field; user reads this and finds out what this line is about. The right side has the value; this acts as the display for the field, also as a button to update/change the value. Each value has its own button tag with unique IDs because they will update/change with JavaScript.

Accessibility

The first edition of the prompt system used to look very different and had a very non-user-friendly system of working. The current one I have impletement was inspired by the one we have in our VLE Blackboard. As you click on the button that says Enter Here, it prompts user what they want to enter there. If it already has a value, clicking on it again asks the user to change it. If the user inputs anything invalid or empty value, it skips it while also not updating the progress.
