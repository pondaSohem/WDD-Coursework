Splash Page

Technical Description

The Splash page is a single full-screen introductory screen that auto-redirects the user to the home page after a 3-second countdown. The page is structured around one main <div> with the ID #splash, which wraps all visible content including the heading, description paragraph, circular countdown loader, and skip button.
The heading uses <h1> with a class of .logo to display the page title. Below it, a <p> tag with ID #para is positioned at the bottom of the screen using position: absolute, bottom: 40px, and transform: translateX(-50%) to keep it horizontally centred.
The circular countdown loader is built using an inline <svg> with a viewBox of 0 0 100 100. It contains two <circle> elements: a static background circle with class .circle-bg, and an animated progress circle with class .circle-progress and ID #circleProgress. The countdown number is displayed in the centre using a <span> with ID #countdown, overlaid on the SVG using CSS positioning within the .circle-container wrapper.
All countdown logic is handled with JavaScript inline in the page. The circle's stroke animation uses strokeDasharray and strokeDashoffset, calculated from the circumference formula 2 * Math.PI * 40 ≈ 251.2. A setInterval() decrements the counter every 1000ms, updates countdown.textContent, and shrinks the visible stroke by adjusting strokeDashoffset proportionally. When the count reaches zero, clearInterval() stops the timer, the .fade-out class is added to #splash triggering a CSS opacity: 0 transition over 0.4 seconds, and window.location.href redirects to the home page after an 800ms delay.
A skip button styled with class .skipbutton is fixed to the bottom-right corner using position: fixed, bottom: 30px, and right: 30px. It has a hover effect that changes its background to #1abc9c and scales it up using transform: scale(1.1). Clicking it triggers the same redirectWithFade() function via an addEventListener("click", ...) with e.preventDefault() to prevent default anchor navigation and ensure the fade transition plays first.

Accessibility

The circular countdown loader provides a visual representation of time remaining without requiring the user to read numbers alone, as the shrinking stroke of .circle-progress gives an immediate visual cue of how much time is left before redirect. The countdown number inside #countdown acts as a text alternative for users who may not perceive the animated SVG stroke, ensuring the remaining time is always readable as plain text. The skip button using class .skipbutton gives users full control to bypass the auto-redirect at any point, which is especially important for users who may need more time to read the introductory paragraph before being redirected. Users can clearly see when they are hovering over the skip button through the :hover pseudo-element, which changes the background colour to #1abc9c and applies a transform: scale(1.1) effect, providing clear visual feedback. The #para description paragraph gives context about the purpose of the website before the user is taken to the home page, ensuring all users including those using screen readers understand the site's intent from the very first screen. The fade-out transition applied through the .fade-out class uses a gradual opacity change rather than an abrupt page switch, reducing visual disruption for users sensitive to sudden screen changes.

Splash Page

Technical Description

The Action Impact Simulator page is structured around two main visible sections: a .feedback panel at the top and a .cards-grid below it, both wrapped inside a .wrapper div that constrains the content to a max-width: 1140px and centres it with margin: 0 auto. Above the wrapper sits a .hero banner using background: linear-gradient(135deg, #0077b6, #009cd9) to introduce the page with a full-width coloured header.
The .cards-grid uses display: grid with grid-template-columns: repeat(auto-fill, minmax(270px, 1fr)) to create a fully responsive card layout that reflows automatically based on viewport width. Each of the seven action cards is a <div> with class .action-card, using role="button" and tabindex="0" so they behave as interactive elements without using an actual <button> tag. Each card holds a .card-img div containing an <img>, a .tick div for the selection checkmark, and a .card-body with a heading, description paragraph, and a .badge showing the point value.
Each card stores its point value in a data-points attribute. JavaScript reads this with getAttribute('data-points') inside the toggleCard() function. Clicking a card adds or removes the .selected class, adds or subtracts its points from totalPoints, and calls updateUI(). Cards are also keyboard operable via handleKeydown(), which triggers toggleCard() on Enter or Space keypress using event.preventDefault() to stop the page from scrolling.
The .feedback panel contains the results area #results, which is hidden with display: none until at least one card is selected. Once active, updateUI() updates #score-num with the current total, sets the #level-pill class to either .low, .medium, or .high depending on the score thresholds (0–6, 7–13, 14+), fills #summary-msg with a message from the MSGS object, and animates the .prog-fill bar by setting its width as a percentage of the maximum 25 points. The fill colour also dynamically changes between orange, yellow, and blue depending on the level.

Accessibility

Each .action-card is given role="button" and tabindex="0" so that keyboard users can tab to and activate every card without needing a mouse. The handleKeydown() function ensures pressing Enter or Space triggers selection, matching expected keyboard behaviour for interactive elements. Each card also carries an aria-label describing both the action name and its point value, and an aria-pressed attribute that updates between "true" and "false" via card.setAttribute('aria-pressed', ...) inside toggleCard(), so screen readers can announce whether a card is selected or not. The .feedback panel uses aria-live="polite" so that when the score, level pill, progress bar, and summary message update dynamically, assistive technologies announce the changes without interrupting the user. The .tick checkmark element carries aria-hidden="true" since it is purely decorative and its information is already conveyed through aria-pressed. Similarly, the decorative SVG icon in the feedback heading uses aria-hidden="true". All card images include descriptive alt text explaining the educational action shown, and each also has an onerror fallback to a placeholder image, ensuring the card remains visually complete even if the asset fails to load. The back to top button includes an aria-label="Back to top" and its hover state expands the label text to "↑ Back To Top" via innerHTML, providing a clear action description for all users.

Content Page

Technical Description

The Content Page covers SDG Target 4.2, focusing on quality early childhood development and pre-primary education. The page is structured entirely within a <main> tag and divided into several distinct <div> sections, each with a dedicated class that controls its own layout and styling via the external content_ST2.css stylesheet.
The page opens with a .top1 div containing an <h1> for the main title and an <h2> with class .h3 for the target description subtitle. This is followed by a .container div which holds a full-width <img> styled inline with width: 100%, border-radius: 8px, and max-height: 300px alongside introductory paragraphs explaining Target 4.2.
The .stats-section presents four key statistics using a .stats-grid containing four .stat-card elements. Each card holds a .stat-num for the figure and a .stat-label for the description, presenting data visually rather than as plain text paragraphs.
The .key-elements-section uses a side-by-side layout with an <img> of class .key-elements-img alongside a .key-elements-content div. Inside it, a <ul> with class .key-elements-list presents six principles of Target 4.2 using <li> items with <strong> tags to bold each principle name.
The .related-targets-section uses a .targets-grid to display six related SDG 4 targets as .target-item cards, each with an <h3> and a <p>. The .challenges-section splits into a .challenges-left div containing text and an inline bar chart, and a .challenges-img image floated to the right. The bar chart is built entirely in HTML and CSS using .chart-container, .bar-row, .bar-track, and .bar-fill elements, with each bar's width hardcoded as an inline style="width: X%" attribute representing the severity percentage.
The .success-section uses a .success-grid to display five country case studies as .success-item cards. The .road-ahead-section mirrors the key elements layout with a .road-ahead-img beside .road-ahead-content. The .help-section lists six actionable steps using .help-item divs, each featuring an .action-badge span alongside a paragraph. The page closes with a .deadline-banner for the 2030 deadline and a .resources-section listing further reading as a <ul> with class .resources-list. The back to top button uses mouseenter and mouseleave event listeners to expand the label to "↑ Back To Top" and change its background to #1abc9c on hover.

Accessibility

The page follows a clear heading hierarchy: <h1> for the page title, <h2> for each major section heading, and <h3> for subsection titles within the .related-targets-section and .success-section cards, giving screen readers a logical document structure to navigate. All four images on the page include descriptive alt attributes such as "Children in a classroom", "Children learning", "Child reading", and "Teacher in classroom", conveying the educational context to screen reader users rather than simply describing visual appearance. The bar chart in the .challenges-section includes percentage values as visible text inside each .bar-fill element, ensuring the data is readable as plain text and not conveyed by visual width alone. The .key-elements-list uses a semantic <ul> with <li> items, allowing screen readers to announce the number of list items and letting keyboard users navigate through each principle individually. The same applies to the .resources-list at the bottom of the page. The back to top button expands its label text to "↑ Back To Top" on hover via innerHTML, providing a clear action description for users who may not recognise the arrow symbol alone. The <main>, <header>, <nav>, and <footer> semantic elements create clear landmarks that assistive technologies use to help users jump between page regions efficiently.

Challenges and Lessons Learned

  • Learning GitHub for collaboration. Before this coursework I had very little experience with pushing and pulling, and ran into several merge conflicts with team members. I now understand branching and communication around commits much better.
  • Integrating JavaScript into the feedback page. I had not worked with DOM manipulation or form validation before, and the live character counter and error messaging took several attempts to get working correctly. Watching tutorials and reading MDN documentation helped me work through it.
  • Building the circular SVG countdown on the splash page. Calculating the correct strokeDashoffset values using the circumference formula took trial and error before the animation synced properly with the countdown timer.
  • Getting the AIS card selection logic right. Managing the .selected state, point addition and subtraction, and keeping the progress bar and level pill in sync required careful structuring of the toggleCard() and updateUI() functions.
  • Passing HTML validation. Several errors came from incorrect nesting, missing alt attributes, and using <p> tags inside other block elements. I debugged these individually using the W3C validator.
  • Aligning layouts across different screen sizes. Getting the card grids, side-by-side image and text sections, and stat cards to respond correctly at smaller viewports required repeated testing and adjustments to the CSS grid and flexbox properties.
